# development

Building features and designing modules. Each skill's tier is a row in [`../skills.csv`](../skills.csv); the full list of categories is [`../README.md`](../README.md).

| Skill | What it does |
|---|---|
| [build-debug-tool](build-debug-tool/SKILL.md) | Turn a repeated hunt through logs, JSON dumps or database rows into a permanent diagnostic tool, at the moment you notice the pain. |
| [hk-mock-first](hk-mock-first/SKILL.md) | Mock a feature's user-facing surface with realistic data, get the user to accept it, then replace the mocks one layer at a time. |
| [hk-refine](hk-refine/SKILL.md) | Improve an output that isn't good enough (a reflection, plan, prompt, pipeline result) by an observe-hypothesize-change-rerun loop kept on disk. |
| [matt-codebase-design](matt-codebase-design/SKILL.md) | Glossary and principles for deep modules: module, interface, depth, seam, adapter, leverage, locality. |
| [matt-domain-modeling](matt-domain-modeling/SKILL.md) | Build and sharpen a project's glossary and domain model, kept in the Language section of the nearest CLAUDE.md, with decisions recorded in docs/patterns/. |
| [matt-grill-me](matt-grill-me/SKILL.md) | Interview the user in rounds until a loose idea, plan or design is one they can commit to. |
| [matt-tdd](matt-tdd/SKILL.md) | Write tests that survive refactors, test-first. |
