# Project powers

**Why.** Point the kit at a fresh webapp tomorrow and every agent starts
naked: no seed scripts, no domain patterns, no deploy checks. The kit should
grow a toolbox around whatever it builds, the way a good team does. This
bucket is the bridge from "the kit builds itself" to "the kit builds
anything."

**Ideas.**
- Project skill packs. As the kit works on a project it accumulates that
  project's skills: seed data, screenshot flows, deploy checks, domain
  patterns. Stored with the project, injected into every future task on it.
- Scaffolds from our own history. The fourth CRUD table isn't written from
  scratch, it's generated from the diffs of the first three.
- A doctor per project. One command that answers "is this project healthy,
  what changed since yesterday," generated and kept current as the project
  grows.
- Curated test sets. A short hand-picked list of scenarios that really
  matter, shown visually, used by agents as the do-not-break list and by
  review as ground truth. Quality of the list is the point, not size.

When an idea here becomes real work, it gets its own section below this
line (or its own file) with the design, the tasks, and the before and after
numbers. The WHY above travels into every task description.
