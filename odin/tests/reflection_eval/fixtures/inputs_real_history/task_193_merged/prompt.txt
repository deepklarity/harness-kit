# Task 193 — needs_human merge reconciliation

## Problem

When the merge agent flags a task `metadata.merge_status='needs_human'`
(ambiguous conflict, watchdog escalation, or Celery broker failure) and the
operator then resolves the conflict by hand, the merge commit lands on the
spec branch but **nothing ever clears the flag**. The board shows phantom
pending merges forever. Root problem: merge state is written once by the
merge agent and never reconciled against git reality.

## Fix (cause, not symptom)

A reconciliation pass that re-checks each flagged task against git: if the
task branch is now an ancestor of the spec branch, the merge happened and
the flag is stale — clear it. It rides the **existing** periodic seam
(`scan_pending_merges` / Celery Beat `merge-watchdog-scan`), not a new cron.

The git primitive lives where all git operations live (odin's
`WorktreeManager`); the orchestration lives beside the existing merge-status
machinery (`tasks/dag_executor.py`).

## Files changed

| File | Change |
|---|---|
| `odin/src/odin/worktree.py` | Added `WorktreeManager.is_ancestor(ancestor, descendant)` — wraps `git merge-base --is-ancestor`; returns True only on exit 0 (any other exit = not merged / unknown ref, never a positive signal). |
| `taskit/taskit-backend/tasks/dag_executor.py` | Added `reconcile_needs_human_merges()` — iterates `metadata__merge_status="needs_human"` tasks, clears the flag + records `merge_resolution` + drops `merge_error`/`merge_ambiguous_files` + posts one STATUS_UPDATE comment when `is_ancestor` is True. Wired into `scan_pending_merges()` (runs before the watchdog) so it uses the existing Beat schedule — no new cron. |
| `taskit/taskit-backend/tests/test_merge_reconciliation.py` | New — 8 tests covering the full scenario matrix. |
| `odin/tests/unit/test_worktree.py` | New `TestIsAncestor` — 3 tests for the git primitive (exit 0 / not-ancestor / missing-ref). |

### What the reconciliation does per task

For each task with `merge_status='needs_human'`:
1. Resolve branch (`task/<spec>/<id>`) + spec branch (`spec/<spec_id>`) + WorktreeManager.
2. If any is missing → skip (leave flagged, no crash).
3. `wt.is_ancestor(branch, spec_branch)`:
   - **True** → clear: `merge_status='merged'`, `merge_resolution='reconciled: branch merged on spec branch'`, drop `merge_error`/`merge_ambiguous_files`, post one STATUS_UPDATE comment.
   - **False/other** → leave flagged (flag still accurate).
4. Idempotent: once cleared, the task is no longer `needs_human`, so the next scan skips it (no duplicate comments).
