# Task 197: Promote gate — resolve `<id>` placeholders in brief artifact paths

## Problem (the wave-4 false-gap)

Every promote-check in wave 4 held on `artifact missing: .proof/task-<id>/`
because the placeholder token from the brief's working protocol was parsed
as a literal filesystem path. The real `.proof/task-<NNN>/` files existed
but were never checked. Five green tasks waited hours on a human.

## Root cause

`extract_artifact_paths(brief)` in `odin/src/odin/promote_check.py`
extracted backtick-quoted paths from the `## Verify` section without
substituting task-id placeholder tokens (`<id>`, `<your-task-id>`,
`<task-id>`). The gate then checked the literal placeholder path
`.proof/task-<id>/` — which never exists — and held.

## Fix

### Files changed

1. **`odin/src/odin/promote_check.py`** — the fix lives here:
   - Added `_TASK_ID_PLACEHOLDERS` constant listing the three angle-bracket
     tokens: `<id>`, `<your-task-id>`, `<task-id>`.
   - Added `_substitute_task_id(path, task_id)` helper — plain string
     replace of each token with `str(task_id)`.
   - Refactored `extract_artifact_paths` into two layers:
     - `_extract_raw_artifact_paths(brief)` — the original extraction
       logic, no substitution, no filtering. Separated so callers that
       need the raw list (to log what was dropped) can get it.
     - `extract_artifact_paths(brief, task_id=None)` — calls the raw
       extractor, substitutes placeholders when `task_id` is provided,
       drops paths that still contain `<`/`>` after substitution. When
       `task_id` is `None`, behavior is unchanged (backward compat).
   - Added `dropped_artifacts: list[str]` field to `PromotionReport`.
   - `build_promotion_report` now passes `task_id` to
     `extract_artifact_paths` and collects dropped paths (raw paths that
     still have angle brackets after substitution) into
     `report.dropped_artifacts`.
   - `render_report` shows dropped paths in a separate section
     ("Dropped artifact paths (template residue, not checked)") —
     informational, never a gap.
   - `render_attachment` includes `dropped_artifacts` in the structured
     payload.

2. **`odin/tests/mock/test_promote_check.py`** — 10 new tests:
   - `TestTaskIdSubstitution` (6 tests): unit tests for
     `extract_artifact_paths` with `task_id` — substitutes `<id>`,
     `<your-task-id>`, `<task-id>`; drops unsubstitutable angle-bracket
     paths; backward compat without `task_id`; mixed
     substituted+dropped.
   - `TestPlaceholderArtifactGate` (4 tests): end-to-end tests through
     `build_promotion_report` — brief with `.proof/task-<id>/` checks
     the real path; leftover angle-bracket path never produces a HOLD
     gap; dropped paths rendered in report body; full wave-4-style brief
     promotes cleanly.

### Why auto_promote.py was NOT changed

`taskit-backend/tasks/auto_promote.py` does NOT duplicate the artifact
parsing. It calls `odin promote-check <task_id>` via subprocess
(`_run_odin_promote_check`, line 170) and parses the CLI's stdout for
the recommendation. The fix in `promote_check.py` is automatically
inherited by auto-promote through the subprocess code path — no
duplicated logic to drift.
