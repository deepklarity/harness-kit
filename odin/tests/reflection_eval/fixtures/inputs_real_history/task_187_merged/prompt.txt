# Task 187 — Wave-planning automation: draft dispatchable briefs from BACKLOG

## What was built

A standalone script, `docs/fable_roadmap/bootstrap/wave_draft.py`, that
deterministically parses `docs/fable_roadmap/BACKLOG.md`'s `## NOW` / `## READY`
`### N. Title — meta` entries and renders a `create_waveN.py`-style loader
draft: `spec` + `TASKS` dicts with title, full brief (Context/Scope/Acceptance/
Verify + the standard working-protocol footer), suggested agent + latest
model (resolved from `taskit/taskit-backend/data/agent_models.json`, never
hardcoded/guessed), and `depends` edges when one entry names another via
`(item N)`.

It is a **standalone script**, not an `odin` subcommand — every existing wave
loader (`create_wave1.py` … `create_wave4.py`) already lives in
`docs/fable_roadmap/bootstrap/` as a standalone script, so this keeps the same
shape rather than inventing a new CLI-registration path for something run
once per wave (Default First / Simplicity is a feature).

The generated file is written to disk only — it never touches the board. The
operator reviews/edits it, then runs it exactly like any other
`create_waveN.py` loader.

## Design decisions worth naming

- **Deterministic parsing only** (per scope item 2) — no LLM call inside the
  parser/selector/renderer. `argparse` reads BACKLOG.md text with regexes for
  the `### N. Title — WS-X · Size Y · suggested: agent [— STATUS]` header
  shape and `**Label.**`/`**Label:**` body sections. Nothing is inferred from
  a model; everything is copied verbatim from the source entry.
- **Fail loudly, never invent**: an entry missing `Scope`/`Acceptance`/`Verify`
  is rejected with a named reason (e.g. `missing required section(s): scope,
  acceptance, verify`) and skipped — never backfilled with placeholder text.
  Entries marked `DISPATCHED(...)` or `BLOCKED(reason)` in BACKLOG.md are
  likewise skipped with the status echoed in the reason. All skip reasons are
  printed to stderr AND recorded in the generated draft's header comment, so
  the operator sees what was left out and why without re-deriving it.
- **Suggested agent is a default, not a requirement** — a well-formed entry
  lacking a `suggested:` field (seen live: `0e`, `0f` in the real BACKLOG)
  still gets drafted, defaulted to `claude` with an inline
  `# agent defaulted — review before dispatch` comment on that line. This
  matches the repo's Default First tenet (suggestive, always overridable) —
  it is a routing choice, not invented acceptance criteria.
- **Model resolution reads `agent_models.json` directly** rather than
  hardcoding a `MODEL_MAP` inside the generator — single source of truth,
  no second place for the model lineup to drift out of sync. An agent with no
  resolvable `default_model` raises `KeyError` (fail loudly) rather than
  guessing.
- **Description rendering is injection-safe.** The straightforward approach
  (nest the assembled brief inside an f-string, like the hand-written
  `create_wave4.py` does for its `COMMON_FOOTER` interpolation) breaks the
  moment any BACKLOG prose contains a literal `{`/`}` — the generated file
  would fail to compile or silently mis-render. `wave_draft.py` instead emits
  a **plain** (non-f) triple-quoted string literal by default (braces are
  inert there — readable multi-line output, matching the hand-authored
  loaders' shape) and falls back to `repr()` only when the text itself
  contains a `"""` or trailing-quote/backslash that would break a
  triple-quoted block. Covered by
  `test_description_survives_braces_in_source_text`.
- **Dependency edges only wire within the drafted batch.** `find_dependencies`
  scans Context/Scope/Acceptance/Verify text for `item N` references and adds
  an edge only when `N` is also selected in this run — a reference to an
  item outside the batch is silently omitted rather than creating a
  `depends_on` pointer to a task that will never exist.
- **`next_wave_id` auto-increments** past the highest existing
  `create_waveN.py` in `bootstrap/`, so the default invocation needs no
  `--wave-id` argument, while still being fully overridable.
