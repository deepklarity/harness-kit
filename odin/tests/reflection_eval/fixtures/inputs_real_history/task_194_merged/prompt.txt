# Task 194 — Per-class failure policy at FAILED transition (W4.4)

## Problem (root cause)

The failure-class tagger labels failures, but a human still decides
requeue/hold — pure toil for transient classes. Live example: a zai
TLS stream error killed a task; the operator requeued it by hand
minutes later. Root problem: classification exists, policy doesn't.

The tagger produced `failure_class` on every FAILED transition but
nothing acted on it. Only `stale_execution` + `agent_execution_failure`
matching the legacy "no ODIN-STATUS" signature auto-retried, via the
type-based classifier in `dag_executor._is_infra_failure`. Every other
transient class (network/TLS/stream errors, truncation, silent hang,
lock race) was left to a human, and the human was right back where
they started: deciding what to do with a `truncation` task.

The fix is at the policy layer: a per-class table (auto_requeue /
reassign / human) consumed by the dispatcher at the FAILED transition
point — the same point where `tag_failure_class` already stamps the
classification.

## Changes

### `taskit/taskit-backend/tasks/failure_policy.py` (new)

- **`FailurePolicy` dataclass** — `action`, `max_retries`,
  `backoff_seconds`, `description`. Frozen so the table is immutable.
- **`DEFAULT_POLICY_TABLE`** — every value in
  `failure_tagger.FAILURE_CLASSES` has an entry. Three action
  partitions:
  - `auto_requeue`: `stale_execution`, `truncation`, `silent_hang`,
    `transport_error`, `lock_race` (bounded retries + optional
    backoff; same assignee + model preserved).
  - `reassign`: `quota_exhaustion` (the actual reassign lives at
    reflection time in `views._maybe_reassign_on_quota_failure` —
    unchanged).
  - `human`: `env_missing`, `timeout`, `worktree_isolation`,
    `disk_exhaustion`, `crash`, `cancelled`, `model_unavailable`,
    `unknown`. Never auto-retry, never auto-reassign; surface for a
    human with an audit comment.
- **`resolve_policy(metadata, overrides=None)`** — looks up the policy
  from `metadata['failure_class']`. Missing key → unknown → human
  (the safe default; auto-retrying an unclassified failure is worse
  than paging the operator). Unrecognised class → human. When
  `overrides` is None, reads from
  `settings.DAG_EXECUTOR_FAILURE_POLICY_OVERRIDES` so the production
  contract (callers don't pass settings) matches the test contract.
- **`apply_failure_policy(task, overrides=None)`** — the dispatcher.
  - `AUTO_REQUEUE` → delegates to `_maybe_auto_redispatch_infra_failure(task, policy=policy)`.
    The policy's `backoff_seconds` stamps `metadata.next_retry_after`.
  - `REASSIGN` → posts a status_update comment naming the class +
    action + "reassign on reflection (or backoff if provider has
    headroom)". The actual reassign is unchanged.
  - `HUMAN` → posts a status_update comment naming the class +
    action + "surface for human review — no automatic retry". Leaves
    the task FAILED.

### `taskit/taskit-backend/tasks/dag_executor.py` (extended)

- **`_maybe_auto_redispatch_infra_failure(task, policy=None)`** —
  extended to take an optional policy. When `policy` is supplied, the
  function uses `policy.max_retries` (instead of the hardcoded
  `INFRA_AUTO_REDISPATCH_CAP`), `policy.description` (audit comment
  wording), and `metadata.failure_class` (class label). When `policy`
  is None, behaviour is unchanged — preserves backward compat for the
  24 existing infra-redispatch tests.
- **FAILED transition hook** — both FAILED sites now call
  `apply_failure_policy(task)` first; if that returns False
  (HUMAN, REASSIGN, or no policy match), the legacy
  `_maybe_auto_redispatch_infra_failure(task)` is the fallback. This
  guarantees the policy table is the source of truth but a stale
  pre-W4.4 task (no `failure_class`) still auto-retries.
- **Cap-reached idempotency** — the policy path sets
  `metadata.policy_cap_reached` (in addition to the legacy
  `auto_redispatch_cap_reached` alias) so both the new and old audit
  queries see the cap event.
- **Strategy trigger** — the auto-requeue path fires
  `strategy.trigger(locked_task)` so the task actually re-runs (not
  just flipped to IN_PROGRESS).

### `taskit/taskit-backend/config/settings.py`

- New settings knob `DAG_EXECUTOR_FAILURE_POLICY_OVERRIDES = {}` —
  per-class dict of field overrides (`max_retries`,
  `backoff_seconds`). Operators tune retry bounds per host without
  code changes. Unknown keys are silently ignored so a typo doesn't
  crash the dispatcher.
