## Root cause + structural fix (round 1, preserved)

`Orchestrator._route_task_api` and `Orchestrator._route_task_config`
filtered `viable_routes` down to the cheapest cost tier and then handed
that pre-filtered subset to `suggest_routing`. The pure suggester knew
how to escalate (its unit tests pinned that contract) but it was never
given the higher-tier names, so escalation never fired. The fix is
structural: pass the full viable pool to the suggester, reserve the
cheapest-tier bucket for the static-fallback path.

## What each change does (file → behaviour)

### `odin/src/odin/orchestrator.py:2848` — `_pick_from_viable_routes`

* **Before** — `_pick_from_tier_candidates(tier_candidates, stats_by_name)`
  accepted only the cheapest-tier names. The suggester couldn't see
  higher-tier agents. Escalation never fired.
* **After** — accepts the full `viable_routes`. Internally:
  1. Computes cheapest tier for the static-fallback bucket.
  2. Asks `suggest_routing` over the **full** sorted candidate-name
     list.
  3. If the suggester returns `RoutingDecision`, picks that agent
     anywhere in the viable pool (escalation works).
  4. If the suggester returns `StaticFallback`, falls back to
     `random.choice` within the cheapest tier (preserves the old
     tier-distribute contract).

### `odin/src/odin/orchestrator.py:_route_task_api` and `_route_task_config`
