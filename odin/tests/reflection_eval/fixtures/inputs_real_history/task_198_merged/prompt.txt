# Task 198 proof — promote-check gate survives `chmod 644` on verify.sh

## Why

Task 195's commit dropped the executable bit on `scripts/verify.sh`. The
promote-check gate spawned the script directly (`subprocess.run([str(verify_script), ...])`),
which requires the execute bit. The gate then crashed with
`PermissionError: [Errno 13] Permission denied` and the task waited on a
human to `chmod +x` — a false HOLD caused by a mode bit the agent can
silently lose (git mode drift, tarball extraction, Windows checkout,
container image without exec).

This task fixes the **cause**: invoke the script via `sh scripts/verify.sh ...`
so only read permission is needed (which git always preserves).

## Files changed

| File | Change |
|---|---|
| `odin/src/odin/promote_check.py` | `run_verify` now builds `cmd = ["sh", str(verify_script), *suites]` instead of `cmd = [str(verify_script), *suites]`. Added a docstring note explaining the contract: the script is invoked via `sh` so the gate survives a 644 script and the cause-class (PermissionError on direct exec) cannot recur. |
| `odin/tests/mock/test_promote_check.py` | Added `import subprocess` and two new tests under `TestRunVerify`:<br>1. `test_run_verify_works_when_script_not_executable` — `chmod 0o644` the script, call `run_verify`, assert suite rows are parsed (gate ran).<br>2. `test_run_verify_invokes_via_sh_not_direct_exec` — monkeypatches `odin.promote_check.subprocess.run` to capture the argv, asserts `cmd[0] == "sh"` and `cmd[1] == str(verify_script)`. This locks the contract so a future refactor can't silently regress to direct exec. |

`scripts/verify.sh` itself was not modified — its purpose is to run the four
suites and emit `_results.txt`; the gate's responsibility is to invoke it
correctly.
